# Design: `willis-compare` — side-by-side Willis vs. model comparison browser

## Problem

`compare_browser.html` (via `tonywebb browse`) compares model outputs against each
other, but there's no page-by-page way to compare a single model's match index
against `match_index_willis.csv`, the hand-built ground truth. `tonywebb evaluate`
computes the matched/missed/surplus data but only renders it as a static Markdown
report — good for a coverage number, awkward for browsing where a specific model
went wrong on a specific page.

## Goal

A new self-contained HTML page, `browser/willis_compare.html`, generated by a new
`tonywebb willis-compare` command, that shows Willis's entries side by side with a
chosen model's entries, page by page, with the scanned image one click away.

## Architecture

New module `tonywebb/willis_compare.py`, following the existing subcommand pattern
(`register_parser(subparsers)` / `run(args)`, registered in `cli.py` alongside
`build_browser`).

```
uv run tonywebb willis-compare \
    --pattern match_indexes/match_index_*.csv \
    --truth match_indexes/match_index_willis.csv \
    --output browser/willis_compare.html
```

**Data prep (Python, reused not reimplemented):**

- Load Willis and each candidate model CSV via `evaluate.load_index()`.
- `evaluate.py`'s per-page exact-then-fuzzy matcher is currently named
  `_match_page` (private). Rename to `match_page` (drop the leading underscore,
  no behavior change) so `willis_compare.py` can import it directly instead of
  reaching into a private function.
- For pages 1–61 (Willis's covered range): run `match_page()` to get
  matched / missed / surplus, same semantics as `evaluate.py`.
- For pages 62–247: there is no Willis data, so every model row on those pages
  gets a distinct status, `unindexed` — kept separate from `surplus` so that
  label continues to mean "on a page Willis actually reviewed, no match found"
  rather than being diluted by 186 pages nobody has checked yet.
- Build one flat list per model of aligned comparison rows:
  `{page, status, content_type, willis: {matchup, date} | null, model: {matchup, date} | null, similarity}`.
- Embed as JSON per model, same pattern as `compare_browser.html`'s `DATA` blob.
  Fully static output, no server required.

## UI

- Model dropdown (populated from the embedded data) selects which CSV's
  comparison is displayed — no regeneration needed to switch models.
- Rows are grouped by page into bordered page-blocks. Each block shows two
  columns — Willis entries on the left, the selected model's entries on the
  right — aligned where matched, with an empty cell on the unmatched side for
  `missed` (Willis-only) and `surplus`/`unindexed` (model-only) rows.
- A "show page image" toggle per page-block lazy-loads the scan from
  `archive.acscricket.com/.../page{page}_5.jpg`, same URL pattern as
  `compare_browser.html`.
- Filters, matching existing browser conventions: search box (matchup / date /
  page), status filter (`all / matched / missed / surplus / unindexed`),
  content-type filter.

## Testing

- `tests/test_willis_compare.py`, following the pattern already set by
  `tests/test_evaluate.py` and `tests/test_build_browser.py`: unit-test the
  data-prep function against small synthetic CSVs — exact match, fuzzy match,
  missed, surplus (page ≤ 61), and `unindexed` (page > 61) classification, plus
  correct JSON embedding.
- Manual check: generate `browser/willis_compare.html` for real using
  `match_index_reconciled_glm.csv` and `match_index_glm52_cleaned.csv`, open in
  a browser, and confirm the two-column layout, dropdown model switch, filters,
  and image toggle all work.
